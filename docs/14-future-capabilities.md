# ACR 未来功能

本文记录 ACR 后续计划补齐的产品能力。它描述的是方向和验收边界，不表示这些能力已经可用于生产环境。

## 1. 宿主实时探针

在 Agent 原生 Hook 之外增加宿主级观测，持续核对工具声明、实际进程和工作区变化。

目标：

- 捕获未经过已注册工具通道的文件变化；
- 将进程、网络和文件操作关联到对应会话与意图；
- 探针失效时明确降低保证等级，而不是继续显示“安全”。

## 2. 自动 Memory Write Gate

在记忆进入共享上下文前执行来源、冲突、时效和敏感信息检查。

目标：

- 自动识别缺少证据或作用域过大的记忆候选；
- 新旧声明冲突时进入争议状态，不静默覆盖；
- 高风险记忆必须经过人工确认后才能跨 Agent 生效。

## 3. 记忆压缩与按需取回

根据任务相关性、使用频率和证据新鲜度管理 Hot、Warm、Cold 三层记忆。

目标：

- 压缩后仍能追溯每条来源 revision；
- 新会话只接收当前任务需要的最小上下文；
- 被纠正或撤回的旧声明不会再次进入提示上下文。

## 4. 多步 Guarded Repair

把当前受控修复扩展为可验证的多步计划，并支持中断恢复。

目标：

- 每一步都声明输入、输出、资源锁和成功条件；
- 崩溃后从证据确认的位置恢复，不盲目重放有副作用的步骤；
- 修复完成后必须重新评估原始操作，不能默认放行。

## 5. 跨文件 Hook 安装事务

对 Claude Code、Codex 和 MCP 配置执行统一预览、原子写入和一致回滚。

目标：

- 所有目标文件先完成语义校验再一起生效；
- 任一写入失败时恢复全部原文件；
- 升级和卸载不覆盖用户已有的无关配置。

## 6. 契约 Schema、签名与分发

冻结稳定的契约线格式，并增加机器可验证的来源和版本信息。

目标：

- 提供 JSON Schema 与兼容性检查；
- 支持可信签名、审批证据和撤销记录；
- 团队可以分发契约包，同时保留项目级覆盖和冲突检测。

## 7. 发布与运维工程

形成可重复构建、安装、升级、验证和回退的正式发布链路。

目标：

- 提供多平台校验过的二进制和校验和；
- 自动验证数据库迁移、Hook 健康和 Guarded 边界；
- 升级失败时保留事件与记忆数据，并能够安全回退。

## 原则

未来能力仍遵循三条边界：安全决策优先确定性、模型只能生成候选、所有结论必须能够回到原始证据。
