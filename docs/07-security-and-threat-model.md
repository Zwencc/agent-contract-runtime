# ACR 安全与威胁模型

## 1. 保护目标

ACR 优先保护：

1. 契约完整性：未审批规则不能执行，已审批规则不能被静默替换。
2. 执行完整性：原操作、修正操作和最终执行操作可区分、可验证。
3. 证据完整性：事件删改可检测。
4. 项目隔离：一个项目的记忆不能默认泄漏到另一个项目。
5. 凭据保密：工具输入输出中的秘密不进入长期日志。
6. 可用性：策略错误不能无限循环或让所有开发工作永久阻塞。

## 2. 不保护的范围

普通本地模式不试图防御：

- 拥有当前用户或 root/管理员权限、并主动篡改 ACR 二进制和数据库的人；
- 用户关闭 Agent Hook 后直接运行命令；
- 宿主 Agent 自身或操作系统中的未知漏洞；
- 未经过 ACR 执行路径的外部进程副作用。

这些场景需要托管配置、最小权限账号、容器/沙箱、远程审计锚定等额外边界。

## 3. 信任边界

不可信输入包括：

- 用户自然语言约束；
- Agent 生成的工具名称和参数；
- 工具输出；
- 项目仓库内的契约文件；
- 第三方 MCP 服务器；
- 模型生成的契约候选；
- transcript 和日志文本；
- 从其他项目导入的状态。

受信组件包括经校验的 ACR 核心、已审批契约版本、明确安装的验证插件和本地数据库事务层。项目仓库本身不是天然受信来源。

## 4. 主要威胁与控制

### 4.1 Hook 绕过或失效

威胁：Hook 未信任、被停用、崩溃或超时，操作继续执行。

控制：

- `acr doctor` 做真实无副作用探针；
- UI/CLI 显示当前保证等级；
- 硬契约要求 Guarded 模式；
- Claude Code 支持时配置 `onFailure: block`；
- Codex Native 模式不虚报 fail-closed；
- 守护进程心跳和降级事件写入审计。

### 4.2 路径绕过

威胁：相对路径、符号链接、大小写、Windows 分隔符或挂载点绕过规则。

控制：

- 绝对路径规范化；
- 尽可能解析真实路径；
- 分别保存词法路径和解析路径；
- 目标不存在时验证最近存在父目录；
- 根据平台处理大小写敏感性；
- 检查项目根逃逸。

### 4.3 命令解析差异

威胁：shell quoting、管道、子 shell、重定向和平台差异导致规则误判。

控制：

- 不以正则表达式作为唯一高风险命令解析器；
- MVP 自动改写限制在白名单命令形态；
- 复杂命令只分类风险，不做语义重写；
- Guarded 模式优先采用结构化 argv 执行；
- 未知语法进入 ASK/DENY。

### 4.4 修正扩大风险

威胁：原操作危险，但自动修正后更危险或改变用户意图。

控制：

- 风险单调性检查；
- 改写后重新运行全部契约；
- 变换器没有任意执行能力；
- 原始与有效输入同时记录；
- 高风险目标变化必须确认。

### 4.5 契约供应链攻击

威胁：恶意仓库提交契约，让 ACR 自动执行攻击命令或外传数据。

控制：

- 仓库契约默认未审批；
- 契约 DSL 不允许任意脚本；
- 自定义插件独立信任和签名；
- 已审批内容以摘要绑定；
- 拉取更新后内容变化触发重新审批；
- 契约无直接网络权限。

### 4.6 日志泄密

威胁：命令、输出、补丁或上下文包含密钥和个人信息。

控制：

- 持久化前统一脱敏；
- 默认密钥模式和熵检测；
- 字段级 `no_record`；
- 原始对象可配置完全不保存；
- 文件权限最小化；
- 导出前二次脱敏；
- 记录 retention 和删除策略。

### 4.7 Prompt/日志注入

威胁：历史工具输出包含“忽略规则”等文本，在回放时影响新 Agent。

控制：

- 历史输出按证据数据封装，不作为系统指令；
- 上下文包区分 contract、fact、untrusted_output；
- 不把工具输出拼接进高优先级指令；
- 限制长度并保留来源；
- 对可疑内容打标签。

### 4.8 并发竞态

威胁：两个 Agent 同时操作，分别检查时安全，组合后违规。

控制：

- 对契约声明的资源键加租约/锁；
- 检查与 Guarded 执行在同一修复事务中；
- 保存预期资源版本；
- 执行前做 compare-and-swap 式重验；
- 超时后状态标记 unknown，不假设失败或成功。

### 4.9 Bootstrap Prompt Injection

威胁：项目文档或旧 Agent 记忆包含恶意指令，诱导初始化模型扩大读取范围、调用工具或激活危险契约。

控制：

- 确定性发现器决定扫描范围，模型不能请求新增路径；
- 抽取模型无工具、无网络、无文件写入权限；
- 使用严格结构化输出并要求精确来源行；
- 远程模型调用前脱敏；
- 模型输出始终为 candidate；
- 硬契约必须单独人工审批；
- ACR 生成文件带 provenance，禁止循环回灌。

## 5. 权限模型

角色建议：

- `observer`：读事件和状态；
- `author`：创建契约草稿；
- `approver`：批准契约；
- `operator`：激活、暂停和授予有限豁免；
- `admin`：管理受信插件和组织策略。

本地单用户模式可以由同一身份承担多个角色，但事件仍记录动作类型，便于未来升级团队模式。

## 6. 数据保留与删除

项目配置应支持：

- 事件元数据保留期；
- 大对象更短的保留期；
- 敏感项目禁用原始输出存储；
- 按项目导出；
- 可验证删除。

删除会打断哈希链。正确做法是保留带原因的 tombstone 和新的签名 checkpoint；若法律或安全要求彻底删除敏感载荷，则事件保留“载荷已删除”的元数据，不能伪装成历史从未存在。

## 7. 安全发布要求

- 提供 `SECURITY.md` 和私密漏洞报告渠道；
- 依赖锁定与 SBOM；
- 发布产物签名和校验和；
- Adapter 支持版本矩阵；
- 契约 Schema 变更有迁移与降级说明；
- 默认不开启网络模型和遥测；
- 遥测必须 opt-in 且不包含工具原文；
- 针对 Hook 输出协议做模糊测试；
- 对修正器做属性测试，验证不会扩大权限范围。

## 8. 安全声明模板

对外文档建议统一表述：

> ACR 在已启用并受信的集成路径内执行契约。Native 模式可能被本地配置、宿主故障或拥有机器权限的用户绕过；需要强制保证时，请使用 Guarded 或托管部署，并结合操作系统级隔离。

该声明应出现在 README、安全文档和每次保证等级诊断结果中。
